# QuotaWatch internal API contract (Swift 5 / iOS 16)

Independent original implementation. No source copied from OpenMinis. Files below must agree; UI/store owner handles persistence, Keychain, notifications and quota HTTP requests. No real credentials in tests or logs.

## Core files (Models.swift / QuotaParser.swift)

Foundation only, portable to macOS swiftc for tests.

- `enum ProviderKind: String, Codable, CaseIterable, Identifiable { case codex, deepseek }`, computed `id: String`, `name: String`, `interval: TimeInterval` (300/600).
- `enum QuotaUnit: String, Codable { case percent, cny, usd, credits }`
- `struct Credential: Codable, Equatable`: optional String `apiKey`, `accessToken`, `refreshToken`, `accountID`, `identity`; optional Date `expiresAt`. All properties default nil so `Credential(apiKey: ...)` works. This type is NEVER serialized into account cache.
- `struct QuotaMetric: Codable, Equatable, Identifiable`: `id: String`, `title: String`, `unit: QuotaUnit`, `remaining: Decimal?`, `resetAt: Date? = nil`, `granted: Decimal? = nil`, `toppedUp: Decimal? = nil`, `unlimited: Bool = false`, `durationSeconds: Int? = nil`.
- `struct QuotaSnapshot: Codable, Equatable`: `capturedAt: Date`, `metrics: [QuotaMetric]`, `plan: String? = nil`, `available: Bool? = nil`, `creditsAvailable: Bool? = nil`.
- `struct AlertRule: Codable, Equatable, Identifiable`: `metricID: String`, `threshold: Decimal`, `enabled: Bool = true`; computed `id: String { metricID }`.
- `struct Account: Codable, Identifiable, Equatable`: `id: UUID = UUID()`, `kind: ProviderKind`, `alias: String`, `remoteID: String? = nil`, `identity: String? = nil`, `snapshot: QuotaSnapshot? = nil`, `rules: [AlertRule] = []`, `resetAlerts: Set<String>? = nil` (enabled reset metric IDs; absent/null in legacy JSON means all off), `latched: Set<String> = []`, `error: String? = nil`, `lastAttempt: Date? = nil`, `nextAllowedAt: Date? = nil`, `requiresAuth: Bool = false`, `revision: UUID = UUID()`, `createdAt: Date = Date()`. Use synthesized memberwise initializers, var fields.
- `enum QuotaError: LocalizedError { case message(String) }` with user-readable errorDescription. Never include response bodies or tokens in errors.
- `enum QuotaParser { static func parse(_ data: Data, kind: ProviderKind, now: Date = Date()) throws -> QuotaSnapshot }` Parse actual DeepSeek and Codex shapes, empty valid arrays are unknown not zero, no silently accepted unrecognized responses. Codex metric IDs `codex.primary.<seconds>` / `codex.secondary.<seconds>` (use primary/secondary if missing duration), extra limits use stable upstream name prefix; credits separate. Reject invalid values, don't sum windows/currencies; explicit allowed false without percent must not imply percentage zero. Use Decimal money and 100-used_percent (clamped 0...100 for valid nonnegative used %). Negative/malformed data rejected or absent, never manufactured values.
- `enum AlertEvaluator { static func evaluate(snapshot: QuotaSnapshot, rules: [AlertRule], latched: Set<String>, interval: TimeInterval, now: Date = Date()) -> (notify: [String], latched: Set<String>) }` threshold <=, fresh data only (<=2*interval), resetAt<=now unknown, missing/unknown windows keep old latch (not rearm); healthy above threshold clears latch; initially-low emits then latches; disabled rules no notify. It may produce prospective latch; store commits latch only after scheduling success.

## UI and reset notification contract

- `NativeMenuButton: UIViewRepresentable` owns a system `UIButton` with `showsMenuAsPrimaryAction`, a real `UIMenu` and `UIAction` children. SwiftUI owns page/sheet/confirmation state. No custom menu presentation or OAuth animation change.
- Overview retains every non-Credits metric, separate currencies, wrapped large text, errors/auth/staleness, pull-to-refresh and confirmed swipe delete. Detail has independent, initially collapsed `DisclosureGroup`s for quota details, Codex-only Credits and account info; critical status stays outside. Unknown, unavailable, zero and unlimited Credits are distinct; DeepSeek never gains a synthetic percentage or Credits section.
- `ResetNotificationPlanner` is Foundation-only: `candidates(accounts:permitted:now:)` validates/deduplicates/sorts; `capacity(otherPending:)` reserves 8 of 64 slots and caps resets at 48; `plans(accounts:permitted:otherPending:now:)` applies both. `enabledIdentifiers` owns delivered notices even after their due time, until disabled/deleted/auth invalidation.
- Only opted-in Codex percentage metrics with a finite future server `resetAt`, a non-future snapshot and no auth failure are scheduled. Duration, unknown reset, reached reset, Credits and DeepSeek never infer a schedule. Transient network errors do not discard valid future schedules.
- `AccountStore.setResetAlert(_:metricID:enabled:)` checks real system permission before enabling, rechecks the account revision after suspension, persists opt-in before reconciliation and reports unavailable future time. Turning off does not require permission. Rename updates content; deletion and verified identity change clear ownership. Identity change resets opt-ins to nil; same-identity login preserves them.
- `NotificationService.reconcileResets(accounts:)` runs a single main-actor worker. Generation guards before mutations and between adds converge to the latest saved accounts after any in-flight stale add. Only `reset-` pending/delivered IDs are touched; existing `low-` and test paths remain separate. Replacing a changed request first removes its obsolete pending request; a failed add surfaces a retry warning, not a false success. OS removal/add APIs are not an atomic transaction: a notification already being delivered during a concurrent edit cannot be recalled reliably.
- Triggers are nonrepeating calendar dates with timezone. No timer infers the next cycle. Cold start, foreground entry and successful archive commits reconcile. Queue-overflow windows require another reconciliation; no killed-app replenishment guarantee. Copy says reset time reached, never restored to 100%.

## Authorization, navigation and refresh gates

- `NotificationService.authorize()` shares one in-flight request, rereads actual settings and only requests when `.notDetermined`; permitted returns without prompting, denied produces a truthful Settings instruction. No custom permission prompt. Reload generation prevents stale publication; the operation uses its returned status, not a possibly outdated published value. Diagnostics never include raw system descriptions or credentials.
- Low-alert Toggle requests through the same service before becoming enabled; saving and reset opt-in revalidate after suspension. `ReminderAuthorization.canCommit(expected:current:)` rejects changed/deleted revisions; current metric type/eligibility is rechecked before persistence. No account archive fields changed.
- `QuotaDisplayRules.detailColumnCount` uses actual non-Credits metric count (1 or 2 columns, accessibility 1); detail is text-only. `resetText` displays server date/time in 24-hour format or reached-time waiting, never estimated/restored.
- `NotificationTap` parses account UUID and verifies existence. `NotificationRoute` retains a cold-start tap and deduplicates delivery keys; root NavigationStack owns path and routing task. Root/detail dismiss their own sheets only after the full login/verification/save transaction finishes; UIKit presentation and transition state gates navigation. Invalid/deleted target returns home without creating accounts. Recent 64 delivery keys are retained in memory, not a persistent history.
- `AccountStore.refresh(_:forced:notificationAt:)` waits for slots for a notification tap and uses `QuotaRefreshPolicy.allows`. Server Retry-After/auth restrictions always win. An unobserved reached reset (`snapshot.capturedAt < resetAt <= now`) bypasses the normal interval only without a prior error. Successful response with the same old reset reverts to ordinary intervals, preventing tick loops; failures retain automatic 5/10-minute and server backoff, manual/tap retries retain 30-second debounce after server cooldown. Successful fetch since delivery satisfies the tap without a duplicate network request. Foreground sleep aligns to a real future reset; notification delivery itself does not run background networking.
